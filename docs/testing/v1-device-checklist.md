## 시나리오

- [ ] 월~금 07:00 알람이 휴가가 아닌 선택 요일에 울린다.
- [ ] `휴가 일정에는 이 알람 건너뛰기`가 꺼진 두 번째 알람은 휴가 중에도 울린다.
- [ ] 하루 종일 하루짜리 `휴가` 일정은 옵션이 켜진 알람만 당일에 건너뛴다.
- [ ] 여러 날 `여름휴가` 일정은 포함된 모든 날짜를 건너뛰고 종료 후 다시 울린다.
- [ ] 알람 직전에 추가한 휴가 일정이 반영된다.
- [ ] 알람 직전에 삭제한 휴가 일정은 알람을 허용한다.
- [ ] 캘린더 권한을 취소하면 fail-open 정책에 따라 알람이 울린다.
- [ ] 화면 켜짐, 화면 꺼짐, 잠금 화면에서 알람이 표시된다.
- [ ] 해제하면 소리와 진동이 중지된다.
- [ ] 다시 알림은 5분 후 한 번 울린다.
- [ ] 재부팅 후 활성 알람이 복구된다.
- [ ] 시스템 시각 또는 시간대 변경 후 다음 실행이 다시 계산된다.
- [ ] 정확한 알람 권한을 나중에 허용하면 활성 알람이 자동으로 재예약된다.
- [ ] 시간 선택창에서 05:00 등 원하는 시각을 정확히 선택하고 저장할 수 있다.
- [ ] 알람마다 쉼표로 구분한 서로 다른 키워드를 저장할 수 있다.
- [ ] 키워드가 일정 제목의 앞·중간·뒤에 포함되어도 해당 알람만 건너뛴다.
- [ ] 키워드가 비어 있으면 캘린더 일정 때문에 알람을 건너뛰지 않는다.
- [ ] 시스템 알람음 선택창에서 알람별 소리를 선택하고 다시 편집해도 선택이 유지된다.
- [ ] 선택한 알람음을 재생할 수 없으면 시스템 기본 알람음으로 울린다.
- [ ] 22시에 다음 날 알람이 `울림 → 건너뜀`으로 바뀌면 일반 시스템 알림이 한 번 표시된다.
- [ ] 다음 반복일에 `건너뜀 → 울림`으로 복귀하면 22시에 복귀 알림이 표시된다.
- [ ] 다음 날 상태가 같으면 22시 시스템 알림이 표시되지 않는다.
- [ ] 22시 이후 캘린더 변경은 추가 알림 없이 실제 알람 시각의 최종 판정에 반영된다.
- [ ] 캘린더가 0개이면 앱 시작, 알람 추가, 알람 수정 때마다 연결 팝업이 표시된다.
- [ ] Google Calendar가 하나 이상 연결되면 연결 팝업이 표시되지 않는다.
- [ ] 설정 화면에서 연결 캘린더와 사용법/도움말을 확인할 수 있다.

## 현재 자동 검증 범위

- 순수 Kotlin 날짜·반복 요일 계산
- 알람별 일정 제목 키워드 매칭과 캘린더 오류 fail-open
- 알람음 선택 URI 전달과 기본 알람음 대체 순서
- Room 매퍼와 DAO 계측 테스트 컴파일
- 저장·활성화·삭제와 AlarmManager 예약 조정
- 알람 실행 순서와 휴가 스킵
- 활성 알람 재예약
- 알람 편집 상태 검증
- 온보딩·시간 선택 UI 및 Room 마이그레이션 계측 테스트 컴파일
