# Calarm Outlook 직접 로그인 연동 설계

작성일: 2026-09-19

상태: 직접 로그인 방식은 사용자 결정 완료. 이 문서는 검토용 설계이며 구현 완료 기록이 아니다.

## 목표와 확인된 요구

- 사용자는 Outlook 앱 동기화 방식 대신 Calarm에서 Microsoft 계정으로 로그인하기를 요청했다.
- 기존 APK는 사용자가 사용 중이며 실기기 확인을 완료한 것으로 취급한다. 이후 변경된 알림 문구를 포함해 기존 기능의 실기기 재확인을 이번 작업의 선행 조건으로 삼지 않는다.
- Google 연결과 저장된 일반·교대 알람을 보존하면서 Outlook의 선택한 캘린더도 동일한 휴가·공휴일·교대 판정에 사용한다.
- Outlook 앱 설치나 Android 캘린더 동기화 설정이 없어도 동작한다.
- Microsoft Entra 앱은 아직 등록되지 않았다. 실제 로그인 검증에는 소유자 계정에서 앱 등록 후 client ID가 필요하다.

## 제안 범위

첫 버전은 개인 Microsoft 계정과 회사·학교 Microsoft 365 계정의 직접 로그인을 지원하되 Microsoft 계정은 한 번에 하나 연결한다. Google 계정은 기존처럼 함께 사용할 수 있다. Microsoft 계정을 바꾸려면 연결을 해제하고 다시 로그인한다.

계정 소유 캘린더의 목록·선택, 로그인 유지, 재로그인, 수동 새로고침, 자동 동기화, 연결 해제를 포함한다. 공유·위임·그룹 캘린더 및 Microsoft 다중 계정은 이번 범위에서 제외한다. 일정 생성·수정·삭제 기능은 제공하지 않는다.

## 사용자 흐름

1. 온보딩 또는 설정의 `Outlook 연결`을 누른다.
2. Microsoft 공식 로그인 화면에서 계정을 선택하고 캘린더 읽기에 동의한다. Calarm에서 시작해 인증 완료 후 Calarm으로 돌아온다. 비밀번호 입력은 Microsoft 인증 화면에서 처리한다.
3. Calarm이 캘린더 목록을 표시한다. 처음에는 기본 캘린더만 선택하며 사용자가 다른 캘린더를 추가 선택할 수 있다.
4. 최초 동기화가 성공하면 연결 상태와 마지막 갱신 시각을 표시하고 알람을 다시 평가한다.
5. 설정에서 캘린더 선택, 새로고침, 재로그인, 연결 해제를 할 수 있다. 실패한 새로고침이 기존 선택을 지우지 않는다.
6. 로그인 취소는 일반적인 사용자 동작으로 처리한다. 동의 거부, 회사 정책상 관리자 승인 필요, 통신 오류는 각각 구분해 안내한다.

Outlook만 쓰는 사용자에게 Android `READ_CALENDAR`를 필수로 요구하지 않는다. 해당 권한은 Google 연결용으로 표시한다. 알림·정확한 알람·전체화면 알람 권한은 계속 별도로 관리한다.

## 인증과 외부 등록

- Microsoft 공식 MSAL Android를 사용하며 브라우저 기반 인증을 우선한다. Outlook 앱 자체를 인증 수단으로 요구하지 않는다.
- public client, single account 모드, 조직 및 개인 계정을 허용하는 `common` authority를 사용한다.
- Microsoft Graph의 위임된 `Calendars.ReadBasic` 권한으로 시작한다. 이 기능에 필요 없는 일정 쓰기·메일 읽기·조직 전체 읽기 권한은 요청하지 않는다.
- MSAL이 토큰 보관과 갱신을 담당한다. 앱 데이터베이스·로그·일반 SharedPreferences에 토큰이나 비밀번호를 별도로 저장하지 않는다. client secret을 만들거나 APK에 넣지 않는다.
- 계정 세션 식별자를 사용해 로그아웃 전 시작한 요청이 로그아웃 후 데이터를 되살리지 못하도록 한다.
- 디버그와 배포용 서명 각각의 redirect URI를 등록한다. client ID 미설정은 명시적인 개발 설정 오류로 처리하며 성공한 연결처럼 표시하지 않는다.
- 실제 등록 값과 단계는 `docs/setup/outlook-app-registration.md`에 정리한다.

## 기존 구조의 변경 지점

현재 `CalendarContractConnectionRepository`와 `CalendarContractEventSource`는 `com.google`만 조회한다. 연결 판정은 Android 캘린더 권한에 묶여 있고 캘린더 ID는 `Long`이다. 클라우드 인증·조회·캐시는 아직 없다.

- Google 경로는 현재 Calendar Provider 구현을 유지한다.
- Outlook 인증, Graph 조회, 선택 저장, 캐시, 동기화를 각각 분리한다.
- 공급자 구분과 계정 식별자를 포함한 캘린더 키를 도입한다. Graph 문자열 ID를 Long 해시로 변환하지 않는다. 기존 Google 선택값은 원래 Long ID에 대응하도록 이전해 유지한다.
- 연결 상태를 Google 권한/조회 상태와 Outlook 로그인/동기화 상태로 나눈다. 어느 한 공급자에 사용 가능한 선택 캘린더가 있으면 연결된 것으로 표시한다.
- UI의 동기식 `getState()`는 저장된 상태만 읽는다. 네트워크 요청을 UI 스레드에서 실행하지 않는다.
- 통합 `CalendarEventSource`가 선택된 Google 일정과 유효한 Outlook 스냅샷을 합친다. 휴가·교대 키워드 규칙 자체는 바꾸지 않는다.
- 연결·해제·선택·동기화 완료 후 기존 재예약 경로를 호출해 일반 알람, 교대 알람, 사전 알림을 일관되게 갱신한다.

## Graph 조회와 일정 의미

- `/v1.0/me/calendars`로 목록을 가져오고 선택한 캘린더별 `/calendarView`로 기간 내 반복 일정의 개별 발생과 예외를 조회한다.
- 모든 페이지를 읽고 성공한 결과만 한 번에 반영한다. 일부 페이지만 받은 상태를 완전한 목록이나 빈 일정으로 저장하지 않는다.
- 조회에 필요한 ID, 제목, 시작·종료, 종일 여부, 취소 여부, 시간대만 보관한다. 취소된 일정은 판정에서 제외한다.
- 시간 일정은 절대 시각으로 변환하고 `[시작, 종료)` 겹침 규칙을 적용한다.
- 종일 일정은 원래 일정 시간대의 달력 날짜와 배타적 종료일을 보존한다. UTC 변환으로 하루 앞뒤로 이동시키지 않는다. 필요한 Windows/IANA 시간대 변환이 불가능하면 조회 오류로 처리한다.
- 다음 페이지 URL은 Microsoft Graph의 허용된 HTTPS 호스트만 따른다. 인증 헤더를 임의 호스트에 보내지 않는다.

## 동기화와 알람 시각의 동작

알람 방송 수신 경로는 네트워크나 Microsoft 로그인을 기다리지 않는다. 이미 저장된 스냅샷으로 판단한다.

- 최초 로그인, 앱 복귀, 수동 새로고침, 캘린더 선택 변경 시 동기화를 요청한다.
- 연결 중에는 네트워크 조건이 있는 15분 주기 WorkManager 작업을 등록한다. Android가 실행을 지연할 수 있으므로 15분 이내 반영을 보장한다고 안내하지 않는다.
- 로컬 날짜 기준 어제부터 앞으로 31일까지의 전체 일정 스냅샷을 갱신한다. 장기간 반복 일정도 조회 기간 내 발생을 포함한다.
- 성공한 마지막 갱신 후 6시간 이내이고 요청 날짜 전체가 조회 범위 안에 있는 스냅샷만 판정에 사용한다. 기기 시계가 갱신 시각보다 과거로 바뀌면 다시 동기화할 때까지 유효하다고 간주하지 않는다.
- 통신 실패 시에도 이 유효 범위의 기존 스냅샷을 사용할 수 있다. 앱에는 갱신 실패와 마지막 성공 시각을 표시한다. 재인증이 필요한 권한 철회·로그아웃 상태에서는 캐시로 연결을 가장하지 않는다.
- 동기화가 실패하거나 캐시가 오래되어도 이를 `일정 없음`으로 처리하지 않는다. 선택된 공급자 중 하나라도 필요한 데이터를 제공할 수 없으면 통합 조회는 실패를 반환한다.
- 조회 실패 시 기존 정책을 유지한다. 일반 알람은 캘린더 경고와 함께 울리고, 교대 알람은 사용자가 설정한 비상 기본 근무 형태만 울린다. 비상 기본값이 없으면 교대 알람은 울리지 않는다.
- 클라우드 일정의 생성·수정·삭제는 다음 성공한 동기화 이후 반영된다. 오프라인 상태에서 서버 최신 일정을 확인했다고 표시하지 않는다.
- 401은 MSAL의 갱신 경로로 한 번 재시도한 뒤 재로그인 필요 상태로 전환한다. 403은 접근/동의 문제, 429는 Retry-After에 따른 재시도, 5xx·네트워크 실패는 제한된 백오프로 처리한다.

## 저장과 연결 해제

Outlook 캘린더 목록, 선택, 일정 스냅샷, 조회 기간, 성공 시각을 별도 Room 데이터베이스에 저장한다. 기존 알람 DB의 버전 6과 알람 데이터를 건드리지 않는다. Outlook 캐시와 인증 데이터는 백업·기기 전송 대상에서 제외하고 기존 알람 백업 동작은 유지한다.

연결 해제는 즉시 해당 공급자를 판정에서 제외하고 동기화 작업을 취소하며 계정별 Outlook 데이터를 삭제한다. MSAL 로그아웃 결과를 처리하고 지연 응답은 세션 식별자로 거부한다. Google 선택과 저장된 알람은 유지한다.

## 검증

- 인증 성공·취소·실패·토큰 갱신·재로그인·로그아웃 및 지연 응답 무효화.
- Google 단독, Outlook 단독, 두 공급자 병용, Google 권한 거부 상태의 Outlook 사용.
- 문자열 ID 충돌 방지, 기존 Google 선택 유지, 선택하지 않은 캘린더 제외.
- 종일 하루/다일, 시간 일정, 자정 경계, 반복/수정/취소, 다중 페이지, 부분 응답 실패.
- 캐시 범위·6시간 경계·재부팅·시계 변경·오프라인·동기화 실패와 기존 오류 정책.
- 일반/교대/사전 알림 경로에서 네트워크를 호출하지 않는지 확인.
- 기존 단위 테스트, 새 인증/조회/통합 테스트, lint, Android 계측 테스트 컴파일, APK 빌드.
- 앱 등록 후 개인 계정으로 실제 로그인·조회·해제를 검증하고, 회사 계정은 접근 가능한 테스트 계정과 해당 조직의 정책 범위에서 검증한다. 검증하지 못한 계정 유형은 별도 표시한다.
