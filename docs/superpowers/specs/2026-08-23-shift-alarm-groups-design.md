# 교대 근무 알람 그룹 설계

## 목표

사용자가 캘린더에 `주간`, `야간`, `새벽` 등 본인이 정한 근무 형태를 등록하면, 같은 교대 그룹에 속한 알람 중 해당 근무 형태의 알람 하나만 울리게 한다. 일반 알람과 기존 휴가·공휴일 건너뛰기 기능은 그대로 유지한다.

## 핵심 개념

### 교대 알람 그룹

교대 근무용 알람을 서로 배타적인 하나의 그룹으로 묶는다. 그룹 이름은 사용자가 정한다. 예: `병원 근무`, `공장 교대`.

한 그룹에는 제한 없이 근무 형태를 추가할 수 있다.

| 근무 형태 예시 | 정확히 일치할 캘린더 제목 별칭 예시 | 알람 예시 |
|---|---|---|
| 주간 | `주간`, `주간근무`, `주간1` | 06:00 |
| 야간 | `야간`, `야간근무`, `야간1` | 18:00 |
| 새벽 | `새벽`, `새벽근무` | 03:30 |

각 근무 형태에는 알람 시간, 반복 요일, 알람음, 점증 볼륨, 다시 울림 시간과 캘린더 제목 별칭을 저장한다. 그룹에는 캘린더 조회 실패 시 사용할 비상 기본 알람 하나를 지정한다.

### 일반 알람

교대 그룹에 속하지 않은 알람이다. 기존 캘린더 키워드 건너뛰기, 휴가, 공휴일, 반복 요일 규칙을 그대로 사용한다. 교대 그룹의 근무 형태와 무관하게 판단한다.

## 캘린더 제목 매칭

교대 근무 형태는 일정 제목 전체가 등록된 별칭과 정확히 일치할 때만 매칭한다.

- 앞뒤 공백은 제거한다.
- 영문은 대소문자를 구분하지 않는다.
- 부분 문자열은 매칭하지 않는다.
- `야간`은 `야간`과 일치하지만 `야간 근무 후 회식`과 일치하지 않는다.
- 일정 설명, 장소, 참석자 필드는 근무 형태 판정에 사용하지 않는다.

기존 일반 알람의 휴가 키워드 검색 규칙은 변경하지 않는다.

## 날짜 기준

근무 형태는 날짜 단위로 판정한다. 월요일 캘린더에 `야간`이 등록되어 있으면 월요일에 설정된 야간 알람이 오전인지 오후인지와 관계없이 야간 근무 형태로 판단한다.

## 실행 우선순위

교대 그룹 알람의 실행 판정 순서는 다음과 같다.

1. 알람 활성화 여부
2. 반복 요일
3. 휴가 일정
4. 공휴일 자동 끄기
5. 해당 날짜의 교대 그룹 근무 형태
6. 일치하는 근무 형태 알람 실행

휴가와 공휴일은 근무 형태보다 우선한다. 알람의 영구적인 활성화 값을 변경하지 않고 해당 날짜의 실행만 건너뛴다.

## 교대 그룹 판정 결과

### 근무 형태 하나 일치

일치한 근무 형태의 알람만 울린다. 같은 그룹의 나머지 알람은 건너뛴다.

### 일치하는 근무 형태 없음

캘린더 조회는 성공했지만 등록된 근무 형태를 찾지 못한 상태다. 그룹의 모든 알람을 건너뛰며 일반 알람에는 영향을 주지 않는다. 이전 날짜에는 근무 형태가 있었으나 다음 날 `근무 형태 없음`으로 바뀐 경우에만 22시 확인 알림을 보낸다. 같은 상태가 이어지면 반복해서 알리지 않는다.

### 근무 형태 중복

같은 날짜와 그룹에서 서로 다른 근무 형태가 둘 이상 발견되면 충돌로 판단한다.

- 해당 그룹의 모든 교대 알람을 건너뛴다.
- 22시에 사용자에게 근무 일정을 확인하라는 시스템 알림을 보낸다.
- 알림에는 충돌한 근무 형태와 캘린더 제목을 표시한다.

예시:

> 내일 주간과 야간 일정이 함께 등록되어 있습니다. 캘린더 근무 일정을 확인해 주세요. 확인 전까지 해당 교대 알람은 울리지 않습니다.

## 22시 알림

22시에는 다음 날 적용될 교대 상태가 현재 날짜의 상태와 실제로 달라질 때만 알린다.

| 오늘 | 내일 | 알림 |
|---|---|---|
| 야간 | 야간 | 없음 |
| 주간 | 주간 | 없음 |
| 야간 | 주간 | 변경 알림 |
| 주간 | 야간 | 변경 알림 |
| 근무 없음 | 야간 | 시작 알림 |
| 야간 | 근무 없음 | 종료 알림 |
| 정상 | 휴가 | 알람 건너뛰기 알림 |
| 휴가 | 정상 | 복귀 알림 |
| 단일 근무 | 중복 근무 | 확인 경고 |
| 중복 근무 | 중복 근무 | 매일 반복하지 않고 중복 상태가 새로 발생하거나 내용이 달라졌을 때만 경고 |

예시:

> 내일부터 주간 근무 알람이 적용됩니다. 오전 06:00 ‘주간 출근’이 울립니다.

근무 형태가 계속 동일하면 매일 반복해서 알리지 않는다.

## 22시 이후 변경

기존 원칙과 동일하게 22시 이후 캘린더가 변경되더라도 추가 시스템 알림은 보내지 않는다. 실제 알람 실행 직전에 해당 날짜의 캘린더를 다시 조회하여 최종 실행 여부를 판정한다.

## 캘린더 조회 실패와 동기화

`근무 형태 없음`과 캘린더 조회 실패는 서로 다른 상태로 관리한다. 조회 실패는 권한 해제, 캘린더 계정 제거, 휴대폰 캘린더 저장소 오류 또는 조회 예외처럼 앱이 정상적인 결과를 얻지 못한 경우다.

- 일반 알람: 기존대로 안전하게 울린다.
- 교대 그룹: 마지막 정상 결과를 임의로 재사용하지 않고 그룹에 지정된 비상 기본 알람만 울린다.
- 22시 조회에 실패하면 캘린더 연결·권한·동기화를 확인하라는 경고를 보낸다.
- 실제 알람 시각에 조회가 실패해 비상 기본 알람이 실행되면 알람 화면과 시스템 알림에 그 사유를 표시한다.

네트워크가 꺼진 것만으로 조회 실패로 판단하지 않는다. 앱은 휴대폰에 동기화되어 저장된 캘린더 데이터를 읽으므로 이미 내려온 일정은 오프라인에서도 사용할 수 있다. 웹 캘린더에는 있지만 휴대폰에 아직 동기화되지 않은 일정은 앱이 확실히 구분할 수 없으므로, 사용자는 그룹 화면에서 마지막 캘린더 동기화 상태와 다음 날 판정 결과를 확인할 수 있어야 한다.

## 화면 구조

메인 화면에는 일반 알람 목록과 별도로 `교대 알람 그룹` 카드를 표시한다.

그룹 카드에는 다음을 표시한다.

- 그룹 이름
- 오늘 적용된 근무 형태
- 다음 알람
- 등록된 근무 형태 개수
- 캘린더 연결 상태
- 근무 없음, 중복, 조회 실패 경고

그룹 상세 화면에서는 근무 형태를 카드로 표시한다. 사용자는 근무 형태 추가·삭제, 정확한 제목 별칭, 시간, 요일, 알람음, 점증 볼륨과 다시 울림을 설정할 수 있다.

## 데이터 경계

필요한 주요 모델은 다음과 같다.

- `ShiftAlarmGroup`: 그룹 이름과 활성화 상태
- `ShiftAlarmGroup`의 비상 기본 근무 형태 ID
- `ShiftTypeAlarm`: 그룹 ID, 근무 형태 이름, 제목 별칭 목록, 알람 설정
- `ShiftDayEvaluation`: 날짜, 정상·없음·중복·조회 실패 상태, 선택된 근무 형태
- `ShiftPreviewState`: 22시 변경 비교를 위한 마지막 판정 상태

교대 그룹 판정은 일반 알람 판정과 별도의 평가기로 구현하고, 휴가·공휴일 판정만 공통 규칙으로 재사용한다.

## 테스트 기준

- 정확한 제목만 일치하고 부분 문자열은 일치하지 않는다.
- 한 근무 형태가 일치하면 해당 알람만 실행된다.
- 일치하지 않으면 그룹 전체가 건너뛴다.
- 그룹 밖 일반 알람은 기존대로 동작한다.
- 휴가가 근무 형태보다 우선한다.
- 두 근무 형태가 발견되면 모두 건너뛰고 중복 상태가 된다.
- 동일 근무 형태가 이어지면 22시 알림을 보내지 않는다.
- 근무 형태가 변경되면 22시 알림을 보낸다.
- 중복 상태가 새로 발생하면 22시 경고를 보낸다.
- 조회 실패 시 지정된 비상 기본 알람만 실행된다.
- 정상 조회 결과가 근무 형태 없음으로 변경되면 한 번만 확인 알림을 보낸다.
- 22시 이후 변경은 실제 알람 시각의 최종 조회에 반영된다.
