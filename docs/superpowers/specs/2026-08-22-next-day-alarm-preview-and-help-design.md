# Work Alarm V1.2 다음 날 알람 안내 및 도움말 설계

## 목표

매일 22시에 다음 날 알람이 캘린더 일정 때문에 건너뛰게 되거나 다시 정상 동작하게 되는 변화를 한 번만 시스템 알림으로 안내한다. 캘린더가 하나도 연결되지 않은 사용자는 앱의 주요 진입 시점마다 연결 안내를 받고, 설정 화면에서 사용법과 연결 상태를 확인할 수 있게 한다.

기존 V1.1의 실제 알람 시각 캘린더 재확인은 그대로 유지한다. 22시 확인은 사전 안내이며 실제 알람 활성화 스위치를 변경하지 않는다.

## 성공 기준

- Android `AlarmManager`가 매일 22시 다음 날 확인을 한 번 실행한다.
- 다음 날 반복 예정인 활성 알람만 확인한다.
- 알람별 일정 키워드로 다음 날 Google Calendar 일정 제목을 검사한다.
- 이전에 저장한 캘린더 건너뛰기 상태와 달라진 알람이 있을 때만 시스템 알림을 보낸다.
- 22시 이후에는 상태 변화 안내 알림을 추가로 보내지 않는다.
- 실제 알람 시각에는 캘린더를 다시 확인해 최종 울림 여부를 결정한다.
- 조회 가능한 지원 캘린더가 하나라도 있으면 연결 안내 팝업을 표시하지 않는다.
- 지원 캘린더가 하나도 없으면 앱 시작, 알람 추가, 알람 수정 때마다 연결 안내 팝업을 표시한다.
- 설정 화면에서 사용법, 캘린더 연결 상태, 연결된 Google 캘린더를 확인할 수 있다.
- 키워드 입력란은 여러 키워드를 쉼표로 구분한다고 명시한다.

## 다음 날 상태 정의

알람의 사용자 설정은 유지하고 날짜별 유효 상태만 계산한다.

- `RING`: 다음 날 반복 요일이며 캘린더 건너뛰기 조건이 없음
- `SKIP`: 다음 날 반복 요일이지만 일정 제목에 알람 키워드가 포함됨
- `UNKNOWN`: 캘린더 권한 없음 또는 조회 실패

비활성 알람과 다음 날 반복 요일이 아닌 알람은 22시 비교 대상에서 제외한다.

각 알람의 마지막으로 확인된 캘린더 건너뛰기 상태를 로컬 저장소에 보관한다. 최초 확인에서 `SKIP`이면 기본 상태 `RING`에서 바뀐 것으로 보고 알림을 보낸다. 최초 확인이 `RING`이면 변화가 없으므로 알림을 보내지 않는다.

이후 비교 규칙:

- `RING → SKIP`: 내일 알람이 울리지 않는다는 알림
- `SKIP → RING`: 내일 알람이 다시 울린다는 알림
- 동일 상태: 알림 없음
- `UNKNOWN`: 이전 상태를 덮어쓰지 않고 알림 없음

다음 날 반복 대상이 아닌 날에는 저장 상태를 변경하지 않는다. 따라서 다음으로 실제 반복되는 날에 휴가가 끝났다면 `SKIP → RING` 복귀를 안내할 수 있다.

## 22시 예약 및 실행 흐름

`AlarmManager`에 앱 전체에서 하나뿐인 다음 22시 확인을 예약한다. 기존 정확한 알람 권한을 사용하고, 정확한 예약이 불가능하면 가능한 가장 가까운 비정확 예약으로 대체한다.

1. 리시버가 22시 확인 이벤트를 받는다.
2. 다음 22시 확인을 먼저 다시 예약한다.
3. 백그라운드 작업에서 다음 날의 활성 반복 알람을 조회한다.
4. 알람별 키워드와 다음 날 캘린더 일정 제목을 비교한다.
5. 저장된 이전 상태와 비교한다.
6. 변화 목록이 비어 있지 않을 때만 시스템 알림을 게시한다.

앱 최초 시작과 시스템 변경 리시버는 다음 22시 확인을 예약한다. 재부팅, 날짜 변경, 시각 변경, 시간대 변경 때도 예약을 복구한다.

## 시스템 알림

알람 울림 채널과 별도의 일반 중요도 알림 채널을 사용한다. 전체 화면 Activity나 반복 소리는 사용하지 않는다.

한 개 변화 예시:

```text
제목: 내일 알람 변경
내용: ‘테스트’ 일정으로 오전 10:10 ‘주말 알람’이 울리지 않습니다.
```

복귀 예시:

```text
제목: 내일 알람 변경
내용: 일정이 종료되어 오전 10:10 ‘주말 알람’이 다시 울립니다.
```

여러 개 변화는 요약 문구와 확장 가능한 상세 목록을 사용한다.

```text
제목: 내일 알람 2개 변경
내용: 캘린더 일정에 따른 변경 내용을 확인하세요.
상세: 10:10 주말 알람 — 울리지 않음
      11:00 늦잠 알람 — 다시 울림
```

Android 13 이상에서 알림 권한이 없으면 알림을 게시할 수 없으며 앱 설정/도움말에서 상태를 안내한다.

## 실제 알람 시각 최종 확인

22시 이후 캘린더 변경은 별도 상단바 알림을 만들지 않는다. 실제 알람이 전달되는 시점에 기존 `ShouldRingAlarmUseCase`가 최신 캘린더를 조회한다.

- 22시에는 울린다고 안내했더라도 이후 일치 일정이 추가되면 실제 알람은 울리지 않는다.
- 22시에는 울리지 않는다고 안내했더라도 이후 일정이 삭제되면 실제 알람은 울린다.
- 권한 없음과 조회 실패는 기존 fail-open 정책에 따라 알람을 울린다.

## 캘린더 연결 상태

V1.2에서 지원 캘린더는 Google Calendar다. 연결됨은 다음 조건을 모두 만족하는 상태다.

1. `READ_CALENDAR` 권한이 허용됨
2. Android Calendar Provider에서 보이고 동기화되는 Google 계열 캘린더가 하나 이상 조회됨

권한만 있지만 조회 가능한 Google 캘린더가 0개라면 연결되지 않음으로 본다. 조회 가능한 지원 캘린더가 하나라도 있으면 팝업을 표시하지 않는다.

향후 Outlook 지원 시 동일한 연결 상태 인터페이스에 Outlook source를 추가하며, 지원 source 중 하나라도 연결되면 팝업을 표시하지 않는다.

## 반복 연결 안내

다음 진입 시점마다 연결 상태를 새로 확인한다.

- 앱의 메인 화면 진입
- 새 알람 추가 화면 진입
- 기존 알람 수정 화면 진입

연결되지 않았으면 모달 안내를 표시한다.

```text
제목: 캘린더 연결이 필요합니다
내용: 일정에 따라 알람을 자동으로 건너뛰려면 Google Calendar를 연결해 주세요.
버튼: 연결하기 / 나중에
```

`연결하기` 동작:

- 권한 요청이 가능한 상태: Android 캘린더 읽기 권한 요청
- 영구 거부 또는 다시 묻지 않음 상태: 앱 권한 설정 화면으로 이동
- 권한은 있으나 캘린더가 0개: 기기의 계정/동기화 설정으로 이동하도록 안내

사용자가 `나중에`를 누르면 현재 화면은 사용할 수 있지만, 다음 명시된 진입 시점에 다시 표시한다. 권한이 없거나 캘린더가 0개여도 알람은 fail-open 정책으로 정상 울린다.

## 설정 및 도움말

메인 화면에 설정 진입 버튼을 추가한다. 설정 화면은 다음 두 영역으로 구성한다.

### 캘린더 연결

- 상태: 연결됨 / 권한 필요 / 연결된 Google 캘린더 없음
- 연결된 Google 캘린더 이름 목록
- 캘린더 읽기 권한 상태
- 알림 권한 상태
- `캘린더 연결/권한 설정` 버튼
- `Outlook Calendar — 준비 중` 표시

캘린더 이름과 계정 정보는 화면 표시 용도로만 조회하며 별도로 저장하지 않는다.

### 사용법/도움말

- 알람은 여러 개 만들 수 있음
- 시간과 반복 요일 설정 방법
- `캘린더 일정에 따라 건너뛰기`는 해당 알람에만 적용됨
- 여러 키워드는 쉼표로 구분함
- 일정 제목의 어느 위치에든 키워드가 하나라도 포함되면 건너뜀
- 매일 22시에 다음 날 상태 변화를 한 번 안내함
- 22시 이후에는 추가 안내가 없고 실제 알람 시각에 최종 확인함
- 캘린더 조회 실패 시 안전하게 알람이 울림

## 키워드 UI 문구

```text
라벨: 건너뛸 일정 키워드
예시: 휴가, 연차, 병가
도움말: 여러 키워드는 쉼표(,)로 구분하세요. 일정 제목에 키워드가 하나라도 포함되면 이 알람을 건너뜁니다.
```

## 데이터 저장

알람 테이블에는 22시 상태를 섞지 않는다. 알람별 사전 확인 상태를 별도 Room 테이블 또는 전용 key-value 저장소에 저장한다.

필요 필드:

- alarm id
- 마지막 유효 상태 `RING` 또는 `SKIP`
- 판단 대상 날짜
- 갱신 시각

알람 삭제 시 관련 상태도 제거한다. 캘린더 조회가 `UNKNOWN`이면 기존 상태를 유지한다.

## 오류 처리

- 캘린더 권한 없음: 변화 알림 없음, 저장 상태 유지, 실제 알람은 울림
- 연결된 캘린더 0개: 변화 알림 없음, 연결 안내 대상
- 캘린더 조회 실패: 변화 알림 없음, 저장 상태 유지
- 정확한 알람 권한 없음: 비정확 예약으로 대체하고 설정 화면에 권한 상태 표시
- 알림 권한 없음: 상태 계산과 저장은 수행하되 시스템 알림은 게시하지 않음
- 기기 재부팅: 활성 알람과 다음 22시 확인 모두 복구

### 단위 테스트

- 다음 날 반복 대상 알람 필터링

- 캘린더가 하나 이상이면 연결됨
- 권한 없음 또는 캘린더 0개면 연결되지 않음

### Android 테스트

- 22시 알람 PendingIntent 예약 및 교체
- 상태 저장 왕복 및 알람 삭제 정리
- 연결 안내 팝업 진입 조건

### 실제 기기 테스트
