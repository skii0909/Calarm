# 역동적 알람 화면·선택형 다시 울림·기기 호환성 설계

작성일: 2026-08-25

대상: SmartWorkAlarm Android 앱

범위: 알람 울림 화면, 일반/교대 알람의 다시 울림 설정, 기기별 작동 진단과 도움말

## 1. 목표

잠에서 막 깬 사용자가 잠금 해제나 알림창 조작 없이 알람의 정체와 조작 방법을 즉시 알아보고, 한 손으로 확실하게 해제하거나 의도적으로 다시 울림을 선택할 수 있게 한다. 동시에 Galaxy S22 Ultra를 우선 실기기 기준으로 삼되 Android 표준 API를 유지하여 Play 스토어에 배포 가능한 기기 범위를 넓힌다.

이번 변경은 다음 세 결과를 제공한다.

1. 잠금화면 위에 표시되는 3분할 알람 화면과 어느 방향으로든 미는 해제 동작
2. 알람별로 켜고 끌 수 있는 5~30분 다시 울림과 3초 길게 누르기 동작
3. 권한·전체화면 표시·정확한 알람·배터리 절전 상태를 사용자가 확인하고 바로 조치할 수 있는 작동 진단

앱 실행 중 외부 서버, 외부 API, 제조사별 비공식 SDK는 사용하지 않는다.

## 2. 확정된 사용자 경험

### 2.1 알람 울림 화면

화면은 세로 3개 영역으로 구성한다.

#### 상단: 알람 정보

- 알람 제목을 가장 크고 굵게 표시한다.
- 제목은 최대 두 줄이며 길이에 따라 글자 크기를 48sp, 40sp, 34sp 수준으로 단계적으로 줄인다.
- 제목이 매우 길면 두 줄 끝에서 말줄임하여 하단 조작 영역을 침범하지 않게 한다.
- 현재 시각과 필요 최소한의 보조 정보만 제목 아래에 표시한다.
- 상태바와 디스플레이 컷아웃을 피하도록 안전 영역 여백을 적용한다.

#### 중단: 다시 울림

- `다시 울림 사용`이 켜진 알람에서만 표시한다.
- `N분 후 다시 울림`과 `3초간 길게 누르기`를 명확히 안내한다.
- 영역을 누르는 동안 3초 진행률을 원형 또는 선형 진행 효과로 보여준다.
- 3초 전에 손을 떼면 진행률이 취소되고 알람은 계속 울린다.
- 3초가 끝나면 햅틱 피드백을 한 번 주고 현재 울림을 중지한 뒤 설정된 N분 후 같은 알람을 예약한다.
- `다시 울림 사용`이 꺼져 있으면 이 영역과 안내 문구를 완전히 숨긴다. 빈 공간은 상단과 하단 영역이 자연스럽게 확장해 사용한다.

#### 하단: 밀어서 알람 해제

- 화면 하단 중앙에 큰 원형 손잡이를 두고 원 안에 `알람 해제`를 크고 굵게 표시한다.
- 손잡이 주변에 2~3개의 동심원 파동이 반복적으로 바깥으로 퍼지며 투명해지는 애니메이션을 적용한다.
- 사용자는 손잡이를 위·아래·왼쪽·오른쪽 및 대각선을 포함한 어느 방향으로든 끌 수 있다.
- 드래그 거리가 화면 크기에 비례한 해제 임계값을 넘을 때만 알람을 해제한다. 방향은 판정 조건이 아니다.
- 임계값 미만에서 놓으면 손잡이는 탄성 애니메이션으로 중앙으로 돌아가고 알람은 계속 울린다.
- 드래그 진행률에 따라 파동 색, 크기 또는 밝기를 바꿔 완료 시점을 예측할 수 있게 한다.
- 임계값 도달 시 강한 햅틱 피드백을 한 번 주고 서비스의 해제 동작을 호출한다.
- 화면 문구로 방향을 별도 지시하지 않는다. 파동과 손잡이 반응으로 드래그 가능성을 전달한다.

### 2.2 입력과 접근성

- 해제 손잡이의 시각적 크기와 실제 터치 영역은 최소 48dp보다 충분히 크게 유지한다.
- 애니메이션은 조작을 막지 않으며, 프레임 저하가 있어도 임계값 계산과 해제 동작은 정상 작동해야 한다.
- 시스템의 애니메이션 축소 설정이 활성화되면 파동의 이동량과 반복 효과를 줄이되 해제 상태 피드백은 유지한다.
- TalkBack에는 손잡이를 `알람 해제` 동작으로, 다시 울림 영역을 `N분 후 다시 울림, 3초간 길게 누르기`로 설명한다.
- 드래그 해제가 어려운 접근성 사용자를 위해 TalkBack의 접근성 클릭 동작으로도 해제가 가능해야 한다. 일반 사용자 화면에는 별도 해제 버튼을 추가하지 않는다.
- 시스템 뒤로가기, 홈 이동, 화면 회전만으로 알람이 정지되지 않는다.

## 3. 다시 울림 데이터와 동작

### 3.1 데이터 모델

일반 알람 `Alarm`/`AlarmEntity`와 교대 알람 `ShiftTypeAlarm`/`ShiftTypeAlarmEntity`에 `snoozeEnabled: Boolean`을 추가한다. 기존 `snoozeMinutes`는 유지하며 5~30 범위로 제한한다.

Room 데이터베이스 버전을 5에서 6으로 올리고 두 테이블에 다음 열을 추가하는 명시적 마이그레이션을 제공한다.

- 열 이름: `snooze_enabled`
- 타입: 정수형 Boolean
- 기본값: `1`
- NOT NULL

기존 사용자는 지금까지 항상 제공되던 다시 울림 기능을 잃지 않는다. 신규 일반 알람과 신규 교대 알람도 기본값을 켜짐으로 시작한다.

### 3.2 편집 화면

- 일반 알람 편집 화면과 교대 근무형 알람 편집 화면에 `다시 울림 사용` 스위치를 둔다.
- 스위치가 켜진 경우에만 5~30분 선택 UI를 표시한다.
- 스위치를 끄더라도 마지막으로 선택한 분 값은 삭제하지 않는다.
- 다시 켜면 이전 분 값을 복원한다.
- 저장, 로드, 복제, 도메인-DB 매핑, 일반-교대 알람 변환의 모든 경로에서 `snoozeEnabled`를 보존한다.

### 3.3 목록과 울림 서비스

- 일반 알람 목록과 교대 알람 카드의 `N분 후` 기능 표시는 다시 울림이 켜진 경우에만 보여준다.
- 울림을 시작하는 Intent와 알림 PendingIntent에는 활성 여부와 분 값을 모두 전달한다.
- UI에서 잘못되거나 조작된 다시 울림 요청이 들어와도 `AlarmRingingService`가 현재 울리는 알람의 `snoozeEnabled`를 확인한다.
- 비활성화 상태에서는 다시 울림 예약을 만들지 않고 울림을 계속 유지한다.
- 활성화 상태에서만 현재 울림을 중지하고 `now + snoozeMinutes`에 정확한 일회성 알람을 예약한다.
- 다시 울린 화면도 최초 울림과 동일한 3분할 화면과 동일한 해제/길게 누르기 동작을 사용한다.

## 4. 잠금화면 및 알람 전달 경로

기존의 `AlarmManager` → 수신/실행 조정 → `AlarmRingingService` → 전체화면 알림 → `AlarmActivity` 경로를 유지한다. 시각 효과 때문에 별도 그래픽 엔진이나 백그라운드 서버를 추가하지 않고 Jetpack Compose 애니메이션과 포인터 입력으로 구현한다.

- `AlarmActivity`는 `setShowWhenLocked(true)`와 `setTurnScreenOn(true)`를 유지한다.
- 전체화면 Intent가 허용된 경우 잠금화면 위에 알람 화면을 즉시 표시한다.
- 전체화면 권한이 없는 경우에도 높은 중요도의 진행 중 알람 알림과 서비스는 유지하며, 앱 실행 시 작동 진단을 통해 해당 권한 설정으로 안내한다.
- 알람 해제 및 다시 울림은 중복 탭이나 중복 Intent가 와도 한 번만 처리되는 멱등 동작이어야 한다.
- 화면 프로세스가 다시 생성되어도 서비스의 현재 울림 정보로 UI를 복구한다.

## 5. 기기 호환성과 작동 진단

### 5.1 지원 원칙

- `minSdk 26`을 유지하므로 기본 설치 대상은 Android 8.0 이상이다.
- 네이티브 ABI, 특정 센서, 특정 제조사 하드웨어를 요구하지 않는다.
- 정확한 설치 가능 기종 목록은 소스만으로 확정하지 않는다. 릴리스 AAB를 Play Console에 올린 후 기기 카탈로그에서 Manifest 조건과 제외 사유를 확인해 확정한다.
- Galaxy S22 Ultra를 첫 번째 실기기 기준으로 사용하되 Samsung 전용 비공식 Intent에 앱 동작을 의존하지 않는다.
- 제조사 절전 정책은 OS 업데이트로 바뀔 수 있으므로 ‘모든 기기에서 무조건 동작’을 보장하지 않는다. 앱은 위험 상태를 감지하고 사용자가 수정할 수 있게 안내한다.

### 5.2 알람 작동 진단 카드

설정/도움말에 현재 앱 디자인과 일치하는 `알람 작동 진단` 카드를 추가한다. 각 항목은 `정상`, `확인 필요`, `이 기기에서는 해당 없음` 중 하나로 표시한다.

진단 항목은 다음과 같다.

1. 알림 권한
2. 정확한 알람 예약 권한
3. 잠금화면 전체화면 알람 권한(Android 14 이상)
4. 앱 배터리 최적화 적용 상태
5. 최근 알람 예약 정보 또는 다음 예약 알람 존재 여부

`확인 필요` 항목에는 `설정하러 가기`를 제공한다. Android 공개 설정 Intent를 우선 사용하고, 해당 화면을 열 수 없는 기기에서는 앱 상세 설정 화면으로 대체한다. 앱은 배터리 최적화 예외를 강제로 요구하거나 임의로 변경하지 않는다.

### 5.3 권한 안내 정책

- 기존 정책대로 필수 권한이 충족되지 않으면 앱 실행 시 점검 팝업을 표시한다.
- 알람 생성·수정 시에도 저장 전에 필요한 상태를 확인한다.
- 팝업은 현재 부족한 항목만 설명하고 해당 공개 시스템 설정 화면으로 이동시킨다.
- 제조사 설정 화면을 열 수 있다는 가정으로 비공식 컴포넌트명을 하드코딩하지 않는다.
- 알림, 정확한 알람, 전체화면 알람처럼 사용자가 명시적으로 허용해야 하는 권한은 앱이 자동 승인된 것처럼 표시하지 않는다.

### 5.4 Samsung 안내

도움말에는 Samsung 기기에서 앱이 `절전 앱` 또는 `초절전 앱`으로 분류되면 알람과 백그라운드 실행이 제한될 수 있음을 설명한다. Galaxy S22 Ultra에서는 다음 항목을 실기기로 확인한다.

- 알림 허용
- 알람 및 리마인더/정확한 알람 허용
- 전체화면 알람 허용(해당 Android 버전)
- 배터리 사용량 설정과 절전 앱 분류
- 화면 잠금 및 Always On Display 상태에서 울림 화면 표시

도움말의 제조사 메뉴 경로는 OS 버전에 따라 이름이 달라질 수 있음을 함께 밝히고, 진단 카드의 공개 설정 링크를 우선 진입점으로 사용한다.

## 6. 예약 복구와 신뢰성

기존의 부팅 완료, 앱 업데이트, 시간 변경, 시간대 변경, 정확한 알람 권한 상태 변경 후 재예약 동작을 유지하고 회귀 테스트한다.

- 알람 예약은 현재 사용 중인 `setExactAndAllowWhileIdle` 경로를 유지한다.
- 다시 울림도 동일한 정확한 일회성 예약 원칙을 따른다.
- 권한이 없어 정확한 예약이 불가능하면 앱이 성공한 것처럼 표시하지 않고 진단 상태를 `확인 필요`로 갱신한다.
- 진단용 최근 예약 상태는 기기 내부 데이터만 사용하며 외부로 전송하지 않는다.
- 진단 정보가 오래됐거나 확인 불가능하면 `정상`으로 추정하지 않고 확인 필요 또는 알 수 없음에 해당하는 설명을 표시한다.

## 7. 오류 처리

- 전체화면 Activity 실행 실패: 서비스와 진행 중 알림을 유지하고 다음 앱 실행 때 전체화면 권한을 안내한다.
- 다시 울림 예약 실패: 울림을 먼저 끄지 않는다. 실패 안내를 화면에 표시하고 사용자가 다시 시도하거나 해제할 수 있게 한다.
- 저장 데이터 범위 오류: `snoozeMinutes`를 5~30으로 보정한다.
- 이전 버전 DB 마이그레이션: 두 알람 종류 모두 `snooze_enabled = 1`로 보존하며 destructive migration을 사용하지 않는다.
- 드래그 중 터치 취소/다중 포인터: 현재 제스처를 취소하고 손잡이를 중앙으로 복귀시킨다.
- Activity 재생성: 길게 누르기 진행률은 초기화해 의도하지 않은 자동 다시 울림을 방지한다.

## 8. 테스트 전략

### 8.1 단위 테스트

- 제목 길이별 글자 크기 단계와 두 줄 제한 계산
- 임계값 미만/이상 및 모든 방향 벡터의 해제 판정
- 3초 미만 해제 시 취소, 3초 완료 시 다시 울림 요청
- `snoozeEnabled = false`일 때 서비스가 다시 울림 요청을 거부
- 5분과 30분 경계 및 범위 밖 값 보정
- 일반/교대 알람 매퍼와 변환에서 활성 여부 보존
- 권한/OS 버전 조합별 진단 상태와 fallback 설정 Intent 선택

### 8.2 DB 및 계측 테스트

- Room 5→6 마이그레이션 후 기존 일반/교대 알람이 모두 다시 울림 켜짐으로 보존되는지 확인
- 다시 울림을 끈 뒤 분 값이 보존되고 다시 켰을 때 복원되는지 확인
- Compose에서 다시 울림 비활성 시 관련 영역과 목록 표시가 없는지 확인
- 드래그 취소, 드래그 완료, 길게 누르기 취소, 길게 누르기 완료의 UI 상태 확인
- 서비스/Activity 재생성과 중복 Intent에서 한 번만 처리되는지 확인

### 8.3 실기기 및 Play 검증

Galaxy S22 Ultra에서 최소 다음 시나리오를 확인한다.

1. 화면 켜짐, 화면 꺼짐, 잠금화면 각각에서 정시 울림
2. 앱 프로세스 종료 후 울림
3. 절전 모드/Doze 진입 후 울림
4. 어느 방향 드래그 해제와 임계값 미달 복귀
5. 다시 울림 켜짐/꺼짐 및 실제 N분 후 재표시
6. 재부팅, 시간 변경, 시간대 변경 후 재예약
7. 각 권한 거부 후 진단 카드와 설정 이동

릴리스 후보 AAB는 Play Console 기기 카탈로그에서 지원/제외 기종과 원인을 확인하고, 사전 출시 보고서로 여러 실제·가상 Android 기기의 충돌, 호환성, 성능 문제를 점검한다. 사전 출시 보고서는 모든 제조사 절전 동작을 보장하는 수단이 아니므로 Galaxy 실기기 알람 테스트를 대체하지 않는다.

## 9. 완료 기준

- 잠금화면에서 전체화면 알람이 허용된 Galaxy S22 Ultra에 3분할 알람 화면이 표시된다.
- 제목이 길어도 조작 영역과 겹치지 않는다.
- 중앙 원을 어느 방향으로든 임계값 이상 밀면 울림이 종료되고, 미만이면 계속 울린다.
- 다시 울림이 켜진 알람만 3초 길게 누르기 UI와 기능을 제공한다.
- 일반 알람과 교대 알람 모두 다시 울림 설정을 저장하고 목록·울림 화면·서비스에서 일관되게 반영한다.
- DB 5→6 마이그레이션에서 기존 설정을 잃지 않는다.
- 도움말/설정에서 권한, 전체화면, 정확한 알람, 배터리 최적화, 예약 상태를 진단하고 가능한 시스템 설정으로 이동한다.
- 기존 캘린더 휴가 스킵, 공휴일 스킵, 교대 그룹 매칭, 22시 변경 알림 동작에 회귀가 없다.
- 앱 런타임에 서버나 외부 API 비용이 발생하지 않는다.

## 10. 제외 범위

- iOS/iPhone 지원
- 원격 서버 기반 알람 전달 또는 기기 상태 수집
