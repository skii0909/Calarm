# 편집 보호·하단 저장·10분 전 오늘만 끄기 설계

## 목표

알람 편집 내용을 실수로 잃지 않게 하고 저장 버튼을 항상 접근 가능하게 유지한다. 일반 알람과 교대 알람이 울리기 10분 전에 시스템 알림을 보내 사용자가 해당 발생 건만 건너뛸 수 있게 한다.

## 범위

- 일반 알람 편집 화면
- 교대 알람 그룹 편집 화면
- 교대 근무 형태 편집 화면
- 일반 및 교대 알람 예약·취소·복구 흐름
- 10분 전 시스템 알림과 알림 액션

서버, 외부 API, 네트워크 저장소는 사용하지 않는다.

## 편집 화면 동작

### 변경 감지

각 편집 ViewModel은 화면에 처음 로드된 값의 스냅샷과 현재 값을 비교해 `hasUnsavedChanges`를 제공한다. 새 항목은 사용자가 기본값을 실제로 변경한 뒤부터 수정 상태로 본다. 저장 또는 삭제가 완료된 뒤에는 수정 상태를 해제한다.

시스템 뒤로가기와 앱 내 탐색 뒤로가기는 같은 처리 경로를 사용한다. 수정 사항이 없으면 즉시 이전 화면으로 이동한다. 수정 사항이 있으면 다음 버튼을 가진 팝업을 표시한다.

- `저장`: 기존 화면과 동일한 검증을 수행한다. 검증에 실패하면 팝업을 닫고 오류 입력란을 표시하며 화면을 유지한다. 성공하면 저장 후 이전 화면으로 이동한다.
- `저장 안 함`: 메모리상의 변경을 폐기하고 이전 화면으로 이동한다. 임시로 만들어진 교대 그룹이 있다면 기존 초안 정리 절차를 수행한다.
- `취소`: 팝업만 닫고 편집을 계속한다.

### 하단 고정 저장 버튼

세 편집 화면은 `Scaffold`의 하단 영역에 저장 버튼을 둔다. 입력 내용과 삭제 버튼은 독립적으로 스크롤되며 저장 버튼은 시스템 내비게이션 영역을 침범하지 않고 항상 화면에 보인다. 스크롤 콘텐츠 하단에는 저장 버튼 높이만큼 여백을 확보한다.

## 10분 전 오늘만 끄기

### 예약 모델

실제 알람 예약 하나마다 동일한 발생 식별자를 가진 사전 알림 예약 하나를 만든다. 발생 식별자는 알람 종류, 알람 또는 근무 형태 ID, 원래 발생 시각으로 구성한다. 이 식별자를 사용해 서로 다른 날짜의 반복 알람과 같은 시각의 여러 알람을 구분한다.

사전 알림 시각은 원래 발생 시각 10분 전이다. 알람을 새로 저장하거나 재계산할 때 사전 알림 시각이 이미 지났지만 원래 알람 시각은 지나지 않았다면 즉시 알림을 표시한다. 원래 알람 시각까지 지났다면 표시하지 않는다.

일반 알람과 교대 알람의 저장, 활성화 변경, 삭제, 다시 예약, 기기 재부팅, 앱 업데이트, 시스템 시간·시간대 변경, 정확한 알람 권한 변경에 기존 알람과 사전 알림을 함께 예약하거나 취소한다.

### 시스템 알림

사전 알림은 소리와 진동이 있는 전용 알림 채널을 사용한다. 알람마다 독립된 알림 ID를 사용하고 다음 정보를 표시한다.

- 제목: `[알람 이름]이 10분 뒤 울립니다`
- 내용: `오늘 이 알람을 끌까요?`
- 액션 `오늘만 끄기`
- 액션 `유지`

`유지`는 알림만 닫고 알람 예약을 그대로 둔다. 사용자가 아무 액션도 누르지 않아도 알람은 예정대로 울린다.

### 발생 건 스킵

`오늘만 끄기`는 해당 발생 식별자를 앱 내부 로컬 저장소에 기록하고 사전 알림을 닫는다. 반복 알람의 활성화 상태나 요일 설정은 변경하지 않는다.

실제 알람 BroadcastReceiver가 호출되면 벨소리·진동·전체 화면 UI를 시작하기 전에 발생 식별자를 조회한다. 스킵된 발생이면 알람을 울리지 않고 스킵 기록을 소비한 뒤 다음 반복 발생을 정상 예약한다. 스킵되지 않았으면 기존 실행 흐름을 유지한다.

오래된 스킵 기록은 조회 또는 기록 시 함께 정리한다. 앱 프로세스 종료와 기기 재부팅 후에도 동작하도록 로컬 영속 저장소를 사용한다.

## 오류 및 권한 처리

- 알림 권한이 없으면 사전 예약 계산은 유지하되 시스템 알림 표시는 생략한다. 기존 앱 권한 안내에서 알림 권한을 계속 요청한다.
- 정확한 알람 권한이 없으면 기존 알람과 마찬가지로 사전 정확 예약도 수행하지 않고 기존 권한 안내를 사용한다.
- 알림 액션이 중복 전달되어도 같은 발생 건을 여러 번 스킵하거나 다음 알람을 손상시키지 않도록 멱등 처리한다.
- 사전 알림 표시 실패가 실제 알람 예약이나 울림을 취소해서는 안 된다.

## 테스트

- 편집 ViewModel의 초기 상태, 변경 감지, 저장 성공·실패, 변경 폐기 테스트
- 뒤로가기 팝업 버튼과 하단 고정 저장 버튼 Compose 테스트
- 일반·교대 알람의 사전 알림 시각 계산 및 10분 미만 즉시 표시 테스트
- 같은 ID의 다른 날짜 발생을 구분하는 식별자 테스트
- `오늘만 끄기`, `유지`, 무응답, 중복 액션 테스트
- 스킵 발생은 울리지 않지만 다음 반복 알람이 예약되는 통합 단위 테스트
- 재부팅·시간 변경 재예약 테스트
- 전체 단위 테스트, Android UI 테스트 컴파일, lint, debug APK 빌드

## 완료 기준

- 세 편집 화면 모두 수정 중 뒤로가기에서 저장·저장 안 함·취소를 선택할 수 있다.
- 세 편집 화면 모두 저장 버튼이 스크롤과 무관하게 하단에 보인다.
- 모든 실제 일반·교대 알람에 10분 전 시스템 알림이 대응한다.
- `오늘만 끄기`는 선택한 날짜의 선택한 발생 건만 건너뛰며 이후 반복은 유지된다.
- `유지` 또는 무응답 시 기존 알람이 정상적으로 울린다.
- 전체 검증을 통과한 v1.10 APK가 생성된다.
