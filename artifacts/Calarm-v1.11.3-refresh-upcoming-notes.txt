Calarm 1.11.3 — 자동 새로고침 및 다음 알람 목록
2026-10-06

변경 사항
1. 앱을 처음 열거나 다른 앱에서 돌아오면 캘린더를 새로고침한다.
2. 내 알람 화면을 아래로 당기면 같은 동기화/갱신을 실행한다.
   고정 450ms 애니메이션 대신 동기화 및 예정 계산 상태에 맞춰 진행 표시를 한다.
   중복 제스처는 진행 중인 동기화 한 번으로 합친다.
3. 기존 큰 NEXT ALARM 카드 아래에 '그다음 알람'을 최대 3개 표시한다.
   앞으로 30일 범위에서 일반/교대 알람을 함께 시간순으로 계산한다.
   설정한 요일, 해당 날짜 공휴일/대체공휴일, 선택 캘린더의 제외 키워드,
   교대 근무 판단, 사용자가 지정한 1회 건너뛰기를 반영한다.
   일회성 알람은 여러 날 반복 표시하지 않는다.
4. 저장된 알람이나 캘린더 내용이 바뀌면 예정 목록을 다시 계산한다.
   마지막 확인 시각과 동기화 상태, 조회 실패에 따른 불확실성을 표시한다.
5. 예정 계산은 조회용이다. 제외일의 OS 알람 예약을 취소하거나,
   '이번 알람 건너뛰기' 기록을 소비하지 않는다. 실제 실행 시 기존 규칙으로 재판단한다.

동기화의 의미
- Google: 선택한 계정의 캘린더 동기화를 Android에 요청하고 기기 캘린더를 읽는다.
  서버 동기화 완료 시점은 Android/Google 동기화 어댑터가 결정한다. 요청 접수를
  서버 동기화 완료로 표시하지 않는다. 나중에 기기 일정이 변경되면 자동 재계산한다.
- Outlook: 연결된 경우 직접 동기화를 시도한다. 실패하거나 시간이 초과되면 상태를
  표시하고 유효한 저장 일정으로 판단한다. 만료/미조회 일정은 확인 필요로 표시한다.
- 조회 불가 시 일반 알람은 기존 실행 정책처럼 울림을 우선하며 경고를 함께 표시한다.
  교대 알람은 기존 비상 기본 유형 정책을 따른다.
- Outlook 저장 범위(32일)보다 짧은 30일을 표시하여 자정 직후에도 유효한 전날
  저장 일정이 단순 범위 초과 때문에 버려지지 않도록 했다.

검증
전체 단위 테스트 446개 통과(실패/오류/건너뜀 0).
에뮬레이터 UI/앱 재진입 테스트 3개 통과.
lintDebug 오류 0, 경고 55(스타일/API/의존성 권고 포함).
assembleDebug 및 APK 서명 검증 성공. git diff --check 성공.
교차 검토에서 발견한 자정 직후 Outlook 조회 범위 문제는 재현 테스트 후 수정했다.
로그: .superpowers/refresh-final-verification.log
추가 테스트: 공휴일/휴가 후 재개, 일회성, 일반/교대 시간순 병합,
조회 시간 제한, 1회 건너뛰기 비소비, 자정 직후 Outlook 저장 일정,
동기화 중복·실패·시간 초과, 실제 화면의 후속 3개 및 당기기,
앱 최초 실행 및 백그라운드에서 복귀 시 자동 새로고침.
기존 Provider 취소 테스트는 Windows Robolectric의 SDK 간 네이티브 폰트 ZIP 초기화
충돌을 피하도록 다른 Provider 테스트와 같은 SDK 30 환경으로 통일했다.
이는 테스트 환경 변경이며 APK의 minSdk/targetSdk를 변경하지 않는다.

설치 후 확인
- 기존 앱을 삭제하지 않고 APK를 업데이트한다.
- 앱을 열어 새로고침 표시와 '마지막 확인' 시각이 바뀌는지 확인한다.
- 화면을 아래로 당겨 같은 동작이 실행되는지 확인한다.
- 큰 다음 알람 아래 후속 알람이 최대 3개 표시되는지 확인한다.
- 선택 캘린더에 제외 키워드 일정을 추가/삭제하고 목록 변화가 반영되는지 확인한다.
  Google 원격 변경은 기기 캘린더에 동기화된 뒤 반영된다.

제한
실제 계정의 네트워크 동기화와 사용자 휴대폰의 제스처/백그라운드 정책은 실기기
확인이 남아 있다. 30일 안에 울릴 일정이 적으면 후속 목록도 3개보다 적게 표시된다.
이전 1.11.2 점검 보고서의 재부팅 첫 잠금 해제·강제 종료 등 실행 제한은 동일하다.
