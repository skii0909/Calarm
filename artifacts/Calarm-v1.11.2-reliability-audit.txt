Calarm 1.11.2 알람 신뢰성 점검
점검일: 2026-10-06 / Asia/Seoul

사용자 요구
- 선택한 요일은 기본적으로 울린다.
- 공휴일 제외 옵션이 켜진 경우 해당 날짜의 국가 공휴일/대체공휴일만 제외한다.
- 선택한 캘린더의 해당 날짜 일정이 설정한 제외 키워드와 일치하면 제외한다.
- 제외일에도 반복 알람 설정은 유지하고 다음 선택 요일을 예약한다.
- 매일 22시에 다음 날을 판단하되, '제외됨/다시 울림' 상태가 바뀔 때만 안내한다.

검사 범위
일반/교대 알람 저장·수정·삭제·활성화, 다음 요일 계산, 국가 공휴일표,
Google 종일/시간 지정 일정과 날짜 경계, 선택 캘린더 보존, Outlook 통합 조회,
실행 시 제외 판단, 30분 전 알림, 22시 상태 변화 안내, 예약 복구,
BroadcastReceiver와 서비스 수명, 알람음 준비·오류·대체 음원, 진단 기록을 검토했다.
전체 정적 검사와 관련 자동화 테스트를 함께 수행했다. 모든 휴대폰/OS 상태를
실측한 검사나 미발생 보증은 아니다.

주요 발견 및 수정
1. 전날 종일 일정이 오늘로 넘어오는 오류
   Google Calendar의 종일 날짜는 UTC 날짜 의미로 처리한다. 단말 시간대로
   단순 변환해서 전날 공휴일이 다음 날 오전까지 겹치던 문제를 수정했다.
   일정 종료 시각은 포함하지 않는 [시작, 종료) 범위를 적용한다.
   10/5 대체공휴일과 10/6 정상 출근 날짜를 회귀 테스트로 고정했다.

2. 공휴일 오탐
   일반 일정 제목 일부에 공휴일 이름이 들어갔다고 자동 제외하지 않도록 했다.
   공휴일 이름과 맞는 종일 일정에 한해 캘린더 공휴일 대체 판단을 한다.
   사용자가 직접 지정한 제외 키워드는 기존처럼 제목 포함 여부로 판단한다.
   2026년 노동절·제헌절 공휴일 변경도 내장표에 반영했다.
   근거: 인사혁신처 2026-04-29 보도자료
   https://www.mpm.go.kr/mpm/comm/newsPress/newsPressRelease/?boardId=bbs_0000000000000029&cntId=4250&mode=view&pageIdx=1

3. 캘린더 지연·실패로 인한 무음
   실행 판단에 시간 제한을 두고 일반 알람은 조회 실패 시 울림을 우선한다.
   Google ContentProvider가 멈추어도 호출을 분리하고 CancellationSignal을 전달해
   알람 실행이 계속 기다리지 않도록 했다. 교대 알람은 지정 비상 유형 정책을 유지한다.
   이미 확인된 내장 공휴일은 캘린더 조회 실패에도 판단할 수 있다.

4. 저장·예약 실패
   DB 저장 전에 기존 알람부터 취소하던 순서를 수정했다.
   예약 결과와 정확한 알람 권한 오류를 확인하고 저장 실패를 화면에 표시한다.
   수정 실패 시 이전 데이터를 복원하고, 교대 그룹은 한 유형 실패 때문에
   다른 유형의 예약 시도까지 중단하지 않도록 했다.
   선택 해제한 캘린더가 잠시 사라졌다 돌아와도 자동 재선택하지 않는다.

5. 현재 알람과 다음 예약 분리
   다음 반복 예약/부가 기록이 실패해도 현재 도착한 알람의 울림을 진행한다.
   복구가 방금 도래한 미처리 예약을 다음 날로 넘기지 않도록 짧은 복구 유예를 둔다.
   처리 완료된 예약 기록은 제거해 실패한 재예약 뒤 같은 알람이 재생되는 것을 막는다.
   앱을 다시 열면 예약 복구를 시도한다.

6. 오디오 재생
   선택 음원 삭제, 권한 상실, 준비 오류 또는 지연 시 다음 음원으로 전환한다.
   최종 대체 음원은 APK에 포함한 기본 소리다.
   외부 음원 준비는 별도 실행기로 옮겨 기본 소리의 준비까지 막지 않게 했다.
   오래된 콜백과 해제 후 콜백을 무시하고, 종료·재시작 시 자원을 정리한다.
   알람 수신 구간의 제한된 wake lock과 서비스 재전달도 보강했다.

7. 전날 안내와 원인 추적
   상태 변화만 안내하고, 실제 발송 성공 이후에 이전 상태를 확정한다.
   지연된 작업이 자정을 넘으면 잘못된 '내일' 안내를 보내지 않는다.
   실제 제외 기록을 이용해 이후 정상 선택 요일의 재개 안내를 보완한다.
   설정의 진단 화면에 최근 20건 수신·소리 실행 요청·제외·오류를 남긴다.
   '소리 실행 요청'은 스피커에서 실제 소리가 났다는 증거와는 구별한다.

검증 중 발견한 테스트 환경 문제
- 첫 에뮬레이터 실행은 6개 중 1개 실패했다. 테스트는 DB에 시/분만 저장하면서
  실제 예약은 현재+5초로 만들어 두었고, 권한 복구 작업과 겹쳤다. 로그상 복구가
  예약을 다음 날로 재계산했을 가능성이 높다. 실제 UI와 동일하게 미래 분 정각으로
  테스트 예약을 수정하고 실패 진단을 보강한 뒤 6개 모두 통과했다.
- 전체 단위 테스트에서 한 테스트가 본문 실행 전에 Robolectric의 네이티브 폰트
  ZIP 초기화 오류(FileSystemAlreadyExistsException)로 실패했다. 그래픽을 사용하지
  않는 캘린더 Provider 테스트에 LEGACY 그래픽 모드를 명시해 재검증했다.
  모드 근거: https://robolectric.org/javadoc/4.17/org/robolectric/annotation/GraphicsMode.html

남아 있는 제한과 확인 항목
- 이번 검증은 에뮬레이터까지다. 사용자 휴대폰의 실제 스피커, 절전 정책,
  화면 잠금·장시간 대기 조건은 새 APK로 실기기 확인이 남아 있다.
- 재부팅 후 첫 잠금 해제 전 실행(Direct Boot)은 지원하지 않는다.
  재부팅 후에는 잠금을 해제해야 하며, 예약 복구가 늦으면 해당 알람을 놓칠 수 있다.
- 앱 강제 종료 후에는 다시 열어야 복구를 시도한다. 전원 꺼짐, 기기 제조사 제한,
  정확한 알람 권한 회수, 알람 볼륨 0, 방해금지/오디오 경로는 코드만으로 보장하지 못한다.
- 저장소/DB 자체 손상, 플랫폼 호출 거절, 복구 작업의 장시간 지연 등에는 여전히
  누락 가능성이 있다. 짧은 복구 유예는 모든 지연 알람을 나중에 울리는 기능이 아니다.
- 예약 기록이 저장되지 않거나 복구가 처리 전 기록을 이미 읽은 극히 짧은 동시
  실행 구간까지 포함한 중복 실행 방지는 아직 보장하지 않는다. 실패한 예약 교체의
  메타데이터 복원 역시 이전 예약 기록을 정상적으로 읽을 수 있어야 한다.
- 국가 공휴일 내장표는 2026~2031 범위다. 이후 연도와 추가 임시공휴일은
  데이터 갱신 또는 연결한 캘린더에 해당 종일 일정이 필요하다.
- 캘린더 공휴일 판정은 일정 이름·종일 여부에 기반하므로 동일 이름의 개인 종일
  일정과 공식 공휴일 일정을 완전히 구분하지 못한다.
- Outlook은 동기화된 스냅샷을 사용한다. 원격 변경이 다음 동기화 전에 반영되지
  않을 수 있고, 실제 직접 로그인에는 Microsoft Entra 앱 등록/client ID가 필요하다.

설치 및 실제 확인
기존 앱을 삭제하지 말고 동일 서명의 APK로 업데이트한다. 앱을 한 번 열어
설정의 권한·다음 예약 시각·진단 기록을 확인한다. 짧은 테스트 알람을 설정하여
화면 잠금 후 실제 소리를 확인하고, 공휴일/키워드 제외와 이후 재개를 확인한다.
사용자가 종전 APK를 실기기에서 사용했다는 사실은 인정하되 이번 변경의
실기기 검증 완료로 기록하지 않는다.
